# Security boundary — v1.1

Default native launch binds only 127.0.0.1. No wallet, signing, private keys or live transaction adapter exists. Provider URLs are fixed and RPC methods are allowlisted. No undocumented Axiom APIs are used.

HTTP verifies peer address, Host and exact browser Origin. Local access is intended for one OS user: another local process can request a session; this is not strong multi-user authentication. Mutations require a random session token with a 15-minute lifetime. At most 64 sessions are retained. The frontend refreshes before mutation. HTTP bodies are capped at 64 KiB of actual ASGI bytes before JSON parsing, including chunked requests. Rate limit is 240 requests/minute process-wide, not per client.

WebSocket requires an allowed Origin and authenticated first message within 5 seconds. Eight connections maximum, counting unauthenticated handshakes; first message <=4096 characters and native Uvicorn frame limit 4096 bytes. Expired sessions close the socket. Tokens are never passed in URLs or explicitly logged. Native Uvicorn has a 64 concurrent-task limit. This is not a comprehensive denial-of-service defence.

Remote mode is OFF. If MERIDIAN_REMOTE_MODE=true is deliberately configured, separate MERIDIAN_READ_TOKEN and MERIDIAN_CONTROL_TOKEN credentials of >=32 characters are mandatory. A read credential cannot request a control session or mutate. A control operation requires both its bearer credential and a valid session token. WS also checks scope credentials. Credentials belong only on the server; the shipped UI has no remote login or embedded secrets. Allowed Host/Origin settings remain local. This is a tested access-policy foundation, not an internet deployment: TLS, identity integration, revocation/rotation, proxy trust, remote host policy and distributed ownership remain prerequisites.

SQLite writes preserve WAL/FULL and transactional order. Database errors rollback batch state and halt trading. Startup reconstructs accounting from fills, checks positions/cash/fees/realized/equity and the exact last decision's snapshot. Missing/inconsistent records fail closed; clear-halt reruns reconciliation. BUY cancels on restart; SELL remains recoverable, with fresh data and exit feasibility checks. Kill and loss limits block entries without disabling otherwise feasible protective exits.

The OS-held database lease prevents two local backend processes, and is released on crash. PostgreSQL locking is only local to the host/working directory: no multi-host safety claim. Runtime queue is memory-only; crash recovery reconstructs durable orders/ledger, not uncommitted provider observations. Journal data is append-only by convention, not cryptographically tamper-evident.

Input contracts reject unknown fields, NaN, malformed mints. SQL is parameterized; token text is escaped by React. No executable model files are loaded. Dependency locks remain unchanged. Prior dependency-audit results are historical evidence, not a fresh vulnerability scan for this stage. Remaining work: tested backup/restore, disk alarms, safe archival/retention and independent security review.
